# راه‌اندازی اتصال سراسری شیت با Cloudflare Worker

نسخه افزونه: WordFlow Sheets Updater 1.0.20

این تنظیم در «تنظیمات عمومی افزونه» قرار دارد و برای تمام شیت‌ها مشترک است. در حالت روشن، دریافت Headerها و تمام دریافت‌های اطلاعات شیت از ورکر عبور می‌کنند. حالت پیش‌فرض خاموش است. با خاموش‌کردن گزینه، اتصال مستقیم گوگل دوباره استفاده می‌شود. واردکردن فایل اکسل محلی به ورکر وابسته نیست.

## ۱. ساخت ورکر

1. در حساب Cloudflare یک Worker بسازید و ویرایشگر کد آن را باز کنید.
2. کل محتوای فایل cloudflare-sheets-worker.mjs را جایگزین کد اولیه کنید. این فایل ES Module است و به نصب کتابخانه نیاز ندارد.
3. در تنظیمات متغیرها و Secrets ورکر، یک مقدار از نوع Secret با نام دقیق WORKER_TOKEN اضافه کنید.
4. برای مقدار آن یک کلید تصادفی ۶۴ کاراکتری بسازید. در ترمینال می‌توانید دستور زیر را اجرا کنید و خروجی را به‌عنوان Secret بگذارید:

```sh
openssl rand -hex 32
```

5. تنظیمات و کد را Deploy کنید و آدرس HTTPS عمومی ورکر را کپی کنید؛ مثلاً https://sheets-proxy.example.workers.dev .

کلید قابل قبول ۳۲ تا ۲۵۶ کاراکتر و شامل کاراکترهای ASCII قابل چاپ بدون فاصله یا خط جدید است. علامت‌های ویژه مانند * و & و % و # و نقطه مجازند. کلید نمونهٔ ثابت و عمومی استفاده نکنید. این Secret مستقل از Google API Key است.

مستندات رسمی Secrets: https://developers.cloudflare.com/workers/configuration/secrets/

## ۲. تنظیم افزونه

1. افزونه را با فایل WordFlow-Sheets-Updater-1.0.20.zip به‌روزرسانی کنید.
2. وارد «شیت و اکسل ← تنظیمات» شوید.
3. در «تنظیمات عمومی افزونه»، گزینه «اتصال همهٔ شیت‌ها از طریق Cloudflare Worker» را روشن کنید.
4. آدرس ورکر را بدون پارامتر و همان مقدار WORKER_TOKEN را در «کلید محرمانه ورکر» وارد کنید.
5. «ذخیره تنظیمات عمومی» را بزنید.
6. برای آزمایش، یکی از شیت‌ها را ویرایش و «دریافت Headerها» را اجرا کنید. تنظیمات اختصاصی شیت، Spreadsheet ID و API Key قبلی آن همچنان استفاده می‌شوند.

در ویرایش‌های بعدی، خالی‌گذاشتن فیلد کلید محرمانه، مقدار قبلی را حفظ می‌کند. این کلید در پاسخ تنظیمات به مرورگر برگردانده نمی‌شود. یک آدرس و کلید برای تمام شیت‌ها کافی است.

## ۳. محدودسازی اختیاری شیت‌ها

در متغیرهای ورکر، ALLOWED_SPREADSHEET_IDS را تعریف کنید و شناسه تمام شیت‌های مجاز را با کامای انگلیسی جدا کنید. اگر این متغیر تعریف نشود، هر شناسه شیت با کلید ورکر معتبر پذیرفته می‌شود. ورکر فقط درخواست خواندن به آدرس ثابت Google Sheets API ارسال می‌کند و پراکسی عمومی اینترنت نیست.

## خطاهای متداول

- HTTP 401: مقدار WORKER_TOKEN در Cloudflare و کلید ورکر در افزونه یکسان نیست.
- HTTP 403: دسترسی شیت یا Google API Key را بررسی کنید؛ همچنین اگر ALLOWED_SPREADSHEET_IDS تعریف شده، شناسه شیت باید در آن باشد. کلید گوگل محدودشده به IP سرور ایران ممکن است درخواست خروجی Cloudflare را نپذیرد. سیاست محدودسازی کلید را متناسب با این مسیر تنظیم کنید و محدودیت API را به Google Sheets API نگه دارید.
- HTTP 503: Secret ورکر تعریف نشده یا قالب آن نامعتبر است.
- HTTP 502 یا خطای ارتباط: آدرس و دسترسی سرور به ورکر و سپس دسترسی ورکر به گوگل را بررسی کنید. بازکردن آدرس ورکر در مرورگر بدون کلید، عمداً 401 می‌دهد و آزمون اتصال کامل محسوب نمی‌شود.

روش دسترسی به شیت همان روش قبلی افزونه با API Key است. ورکر مجوز دسترسی به شیت خصوصی ایجاد نمی‌کند. در حالت روشن، برگشت خودکار به اتصال مستقیم وجود ندارد؛ برای استفاده مستقیم گزینه را خاموش کنید.

## بررسی انجام‌شده

- ساخت نسخه تولیدی رابط و بررسی TypeScript موفق بود.
- بررسی نحوی ۱۵ فایل PHP برای PHP 8.1 موفق بود.
- بررسی تنظیم سراسری، مسیر مستقیم و ورکر، حفظ کلید خالی، مخفی‌بودن کلید در پاسخ، خاموش‌کردن ورکر و خطاهای اتصال با پاسخ‌های شبیه‌سازی‌شده موفق بود.
- آزمون‌های ورکر شامل احراز هویت، محدودیت شناسه و اندازه ورودی، مسیر ثابت گوگل، خطاهای گوگل و جلوگیری از Redirect موفق بودند.
- اتصال واقعی با شیت و حساب Cloudflare شما و مسیر شبکه سرور ایران در این محیط آزمایش نشده است.

## اصلاحات نسخه 1.0.20

اعتبارسنجی کلید ورکر در افزونه و خود ورکر اکنون علامت‌های ویژه ASCII را می‌پذیرد. کلید پنل هنگام ارسال به REST با Base64 کدگذاری و سمت سرور به مقدار اصلی برگردانده می‌شود؛ این کار رمزگذاری امنیتی نیست و اتصال همچنان با HTTPS است. مقدار WORKER_TOKEN در Cloudflare و فیلد کلید در افزونه باید هر دو همان کلید اصلی باشند، نه Base64 آن.

برای ارتقا، هم افزونه و هم کد ورکر را به‌روزرسانی و ورکر را دوباره Deploy کنید. Secret را با همان مقدار اصلی تنظیم کنید.

پیام HTTP 400 غیر JSON معمولاً نیازمند بررسی پاسخ وب‌سرور یا فایروال است. کدگذاری کلید احتمال برخی خطاهای مربوط به کاراکترها را کاهش می‌دهد؛ علت سرور اصلی بدون لاگ تأیید نشده است. اگر خطا باقی ماند، زمان دقیق ذخیره، پاسخ درخواست general-settings در Network مرورگر و رویداد متناظر لاگ وب‌سرور/ModSecurity را بررسی کنید. هدرهای Cookie و Nonce و کلید محرمانه را هنگام اشتراک گزارش حذف کنید.

در نسخهٔ 1.0.20 خطای تعریف‌نشدن Secret، نامعتبر بودن Secret، یکسان‌نبودن کلیدها، پاسخ خطای گوگل و پاسخ غیر JSON با پیام‌های جداگانه گزارش می‌شوند. ذخیره تنظیمات به معنی آزمون اتصال نیست.
